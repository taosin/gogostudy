# 知识世界的音视频

## 作用与位置

音视频帮助孩子听清任务、观察变化，再回到身边的操作与思考。它们沿用当前地点和问题，不增加独立的视频首页，也不要求观看后才能继续。

| 位置 | 内容 | 后续行动 |
| --- | --- | --- |
| 首页六个地点的发现区 | 当前任务的朗读；英语港湾提供英文问候示范 | 继续点选、排序、行走或转动地球 |
| 数字工坊与数学「数一数」 | 不重不漏地数五只萤火虫的小动画 | 自己逐个点数，再换身边物品试试 |
| 星空观测站与昼夜实验 | 同一地点朝向或背向太阳的变化 | 转动模型，预测观察点是白天还是黑夜 |
| 水循环实验与地理「顺着水流」 | 蒸发、凝结、降水、汇流的一条示意路线 | 操作实验；回到水流方向、上游与下游的问题 |
| 五个学科的「看一看」 | 原有故事的朗读 | 保留原来的动手探索与理解练习 |
| 短片下方 | 完整文字讲解与可选朗读 | 可以不播放视频，直接阅读和学习 |

「看过」或「听过」不会写入课程完成记录。是否完成一课，仍由原有理解练习判定。

## 儿童使用体验

- 孩子主动打开短片并点击播放；进入网页、换地点、刷新和返回页面均不自动发声或播放。
- 使用浏览器原生播放、暂停、进度和全屏控制，手机允许在页面内播放。
- 短片入口默认折叠，让当前任务与操作教具保持清楚。展开后仍可直接继续课堂。
- 动画保留文字说明，同时提供独立字幕与完整讲解。低音量、不方便听声音、播放失败时，学习内容仍然可读。
- 同一页面只保留一个正在播放的音视频或朗读。切换内容、关闭短片、切到后台时停止或暂停，回来后由孩子重新开始。
- 首页的操作状态、学习步骤和错题数据不受媒体加载失败影响。

视频和模型里的大小、距离、速度经过简化。昼夜片段解释地球自转与照明的关系；水循环片段只展示一条可能路径，不代表每滴水都按相同路线、相同时间走完一圈。

## 媒体文件与更新

首批三段动画为项目原创，静态文件放在 `public/media/learning/v1/`。清单由 `lib/learning-media.ts` 管理，播放器统一使用 `components/media/learning-video.tsx`。发布的视频不依赖第三方视频平台、广告播放器或嵌入网页。

| 短片 | 时长 | 编码 |
| --- | --- | --- |
| 五个光点，一个也不漏 | 24 秒 | 960 × 540，20 帧/秒，H.264 |
| 我的白天，去了哪里？ | 28 秒 | 960 × 540，20 帧/秒，H.264 |
| 跟着水，去旅行 | 32 秒 | 960 × 540，20 帧/秒，H.264 |

三段均为静音动画，中文讲解文字直接呈现在画面中；另附可切换字幕，默认不叠加第二层字幕。需要声音时，可以使用完整文字讲解下的朗读。选择朗读会暂停视频，避免两个内容同时吸引注意力。

每段短片保留可播放文件、封面、WebVTT 字幕和文字讲解。短片内容应与现有故事、教具和理解练习使用同一套概念；例如，水蒸气不可见，可见云由微小水滴或冰晶组成。

`scripts/generate-learning-media.py` 保留生成脚本与字幕原稿。重新生成需要 Python、Pillow、ffmpeg 与本地中文字体；脚本不把字体文件分发到网站。MP4 使用适合渐进播放的 faststart 排列。资源测试限制单段视频不超过 2 MiB、三段合计不超过 5 MiB、单张封面不超过 200 KiB；增加更长内容时应先重新评估加载方式与预算。

新增短片时：

1. 先确定它要解释的一个问题，以及看完后可以操作或回答什么。
2. 制作短片与文字讲解，核对科学事实、语言和画面中的模型局限。
3. 加入媒体清单，在最相关的现有学习位置接入。
4. 检查手机上的画面文字、字幕、时长和文件体积。
5. 完成下方验收，再发布。

`v1` 路径使用一年浏览器缓存与 `immutable`。**已发布的文件不得在原路径替换内容**；修订动画、字幕或封面时使用新的版本目录，并一起更新清单。这样已经缓存文件的设备也能拿到新内容。

## 朗读

朗读使用浏览器的 Web Speech API。页面只在孩子点击按钮后开始朗读，不申请麦克风权限，不录音，也不上传孩子的回答。

可用声音、音质和语言支持取决于浏览器与系统。声音列表可能稍后才到达，因此组件需要处理 `voiceschanged`；优先使用匹配语言的本地声音。浏览器也可能提供远程声音，不能把整个朗读功能承诺为完全离线。不支持朗读或没有相应声音时，保留文字并给出清楚提示。[MDN：声音列表](https://developer.mozilla.org/en-US/docs/Web/API/SpeechSynthesis/getVoices)、[本地与远程声音](https://developer.mozilla.org/en-US/docs/Web/API/SpeechSynthesisVoice/localService)。

英文问候按英文语言设置朗读，避免用中文声音读整段英文。普通故事中的混合中英文仍可能因系统声音而有不同表现；本轮不把朗读作为发音评分或语音识别。

## 加载、缓存与部署

- 折叠时不挂载 `<video>`；展开后的 `preload="none"` 提示浏览器不要预先加载整段视频。使用固定宽高比例，减少画面加载时的布局跳动。`preload` 是浏览器提示，不能仅凭属性宣称某个浏览器完全没有请求媒体。[MDN：video](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/video)
- 视频、封面与字幕使用站内路径，避免外部播放器与跨域字幕的额外依赖。字幕使用 `text/vtt`，视频使用正确媒体类型。同源字幕不需要额外的跨域配置。[MDN：track](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/track)
- 当前仓库没有限制同源媒体的 CSP。若以后增加 CSP，需保留 `media-src 'self'`，并检查字幕与封面请求；不能为了视频放宽成任意远程来源。
- Next.js 的 `public` 文件默认是 `Cache-Control: public, max-age=0`，当前配置只对版本化媒体路径设置长期缓存，不扩大到学习进度 API 或用户数据。该默认值已核对本项目安装版本的 `node_modules/next/dist/docs/01-app/03-api-reference/03-file-conventions/public-folder.md`。
- Vercel 静态文件由其 CDN 提供，不需要新增读取大文件的应用 API。分段请求要验证真实的 `206 Partial Content` 和 `Content-Range`，不能只人为添加 `Accept-Ranges`。
- 普通资源请求检查缓存响应；`Range` 请求的主要验收标准是正确返回所需字节。Vercel 文档的一般缓存判定排除了带 `Range` 的请求，因此不要求每个视频分段请求都显示 `HIT`。[Vercel：CDN 缓存](https://vercel.com/docs/caching/cdn-cache)

同源文件减少了第三方平台依赖，但国内实际播放速度仍受用户网络与站点线路影响，本轮不能据此保证所有地区的速度。

## 验收清单

以下是发布前需要执行的场景，**不是已通过的结果**。本轮实测结果统一记录在 [VERIFICATION.md](./VERIFICATION.md)。

### 内容与交互

- 三段短片均可播放、暂停、拖动进度、重新播放；不自动循环或续播。
- 每段画面文字、可切换字幕、完整讲解内容一致，无错误编码、裁切或双字幕遮挡关键画面。
- 数数片段强调每只只数一次、最后一个数表示总数；昼夜片段不把夜晚解释成太阳消失；水循环片段不把可见的云画成可见水蒸气。
- 点击另一段朗读时，前一段朗读或视频停止；点击视频播放时，朗读停止。
- 关闭短片、切换地点、切换课堂步骤、切换实验、离开页面、切到后台后，不继续在后台发声。
- 错误、空声音列表、语言不匹配和媒体失败都有文字替代；重试不会自动发声。
- 播放和听读不会增加完成课程数、覆盖未提交答案或改变错题记录。

### 手机与可访问性

- 在 320、390、768 和桌面宽度检查，展开的播放器、字幕和朗读控制不会导致横向滚动。
- 用键盘打开短片、访问播放控制和文字讲解；按钮有清楚名称与可见焦点。
- 减少动态效果偏好下仍需主动播放，不加入自动动画或闪烁音效。
- 检查移动端全屏、页面内播放和前后台切换；Safari/iOS 未实际测试时不能声称已覆盖。

### 网络与生产环境

- 首屏和未展开区域不下载整段短片；开启多个短片不会导致多路播放。
- 普通 GET 返回正确 `Content-Type`、文件长度和版本化缓存头；字幕内容以 `WEBVTT` 开头。
- `Range: bytes=0-1023` 返回 206、正确 `Content-Range` 与 1024 字节正文；对每段 MP4 分别验证。
- 本地正式构建与线上部署分别验证，不能用开发服务器的行为代替生产结果。
- 全站类型检查、静态检查、既有单元与服务测试通过，正式构建通过。
