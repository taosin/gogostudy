# GoGo 学堂：首期范围与扩展方案

## 已实现的学习闭环

1. 默认课程为浙江省 / 人教版 / 二年级 / 上册 / 数学。
2. 今日练习选取 5 个知识点的题目，优先选择尚未答对的题；也可选择单个知识点。
3. 每题可以看提示，提交后显示判分与讲解；输入答案在保存失败时保留，可重试。
4. 错题自动归入待订正。订正可以记录“计算时出错 / 题目没读清 / 方法还不熟 / 单位或时间弄混”。
5. 订正答对进入待复习。至少间隔 24 小时后以复习模式再次答对，标记已掌握。再次答错回到待订正。
6. 复盘页展示练习正确率（不含订正和复习）、知识点正确率、最近记录、复习计划和学习小记。

## 首期边界

- 题库为原创固定示例，覆盖加减法、乘法、长度、角、观察、时间、搭配。并非完整教材题库，不复制教材原题。
- 省份是学习资料筛选维度，不代表浙江所有学校统一使用同一本教材。
- 人教版不同修订版本可能调整内容和单元顺序；当前按知识点组织，下一步应核对实际课本的版权页、ISBN 和目录后增加 revision 字段。
- 支持数学先行；语文以及其他组合显示准备中。
- 每个家长账号一个学习空间，暂不包含多孩子档案或教师管理。
- 未配置或未登录时使用本机体验记录，正式登录使用 Supabase。两种数据不会混淆或自动合并。
- 云端历史读取最多 50,000 条，超过会明确报错；学习小记显示最新 100 条。后续大规模使用应增加分页和聚合查询。
- 练习记录 RLS 允许用户写自己的数据，不是竞赛防作弊系统；若未来增加排行榜，改为受控判题写入与服务端可信时间。

## 扩展顺序

### 1. 核对教材并扩充数学题库

按 curriculum（省份、出版社、修订版、年级、册次、科目）→ unit → knowledge_point → question 建立目录。题目使用稳定 ID、内容版本和审核状态，已提交记录保留题目快照，避免修改题库后历史错乱。扩充同知识点变式题，避免只记答案。

### 2. 完善账户与家长使用

接入真实 Supabase 项目后，验证两个账号之间的数据隔离、验证码过期、网络失败、刷新持久化、多设备同步。随后增加孩子档案，所有学习表补充 student_id 并通过家长关系做 RLS。访客记录导入必须由家长主动选择，并使用事务去重。

### 3. 语文

保持课程、学习记录与复盘框架，题型扩展为拼音选择、识字词语、句子排序与阅读理解。客观题自动批改；开放题先由家长反馈，不能用简单字符串匹配当作语文理解判分。

### 4. 更完整的复习

增加 1 / 3 / 7 天复习节奏、同知识点变式、薄弱点统计。小学生侧只呈现“今天做什么”；较详细统计放入家长视图，避免排名与倒计时压力。

## 技术约定

原生 Next.js App Router 部署到 Vercel，Supabase 提供 Auth 和 PostgreSQL。初期题库保存在服务端代码，后续迁入数据库时保持 API 的公开题目结构。客户端不能在题目列表接口中获得答案；提交后才返回解释。所有用户写入通过验证 token 的接口与 RLS；不在客户端配置 service role key。
